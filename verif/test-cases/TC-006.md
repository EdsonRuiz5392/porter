# TC-006 — Capturar stdout, stderr y código de salida

**Requisitos cubiertos:** RF-11 (capturar stdout y stderr sin mezclarlos y permitir su consulta), RF-07 (código de salida).
**Nivel:** integración y sistema. **Hito:** H1.

## Objetivo
Comprobar que la salida estándar y la de error de un trabajo se guardan por separado, que se pueden consultar, y que el código de salida registrado coincide con el real, incluido el caso de terminación por señal.

## Precondiciones
Servicio arrancado según la preparación común, `/tmp/porter-tc` limpio.

## Entorno y configuración
Preparación común.

## Datos de entrada
| Trabajo | Comando (como lo recibe el CLI) | Espera |
|---|---|---|
| A | `sh -c 'echo linea-out; echo linea-err >&2; exit 3'` | stdout=`linea-out`, stderr=`linea-err`, código 3 |
| B | `sh -c 'for i in 1 2 3; do echo out$i; echo err$i >&2; done'` | salidas intercaladas, sin mezclarse, código 0 |
| C | `sh -c 'kill -9 $$'` | muere por SIGKILL, código de señal |

## Pasos reproducibles
1. `porter submit sh -c 'echo linea-out; echo linea-err >&2; exit 3'` → ID-A.
2. `porter submit sh -c 'for i in 1 2 3; do echo out$i; echo err$i >&2; done'` → ID-B.
3. `porter submit sh -c 'kill -9 $$'` → ID-C.
4. `sleep 2`. `porter status` de A, B y C.
5. Consultar la salida de A: con el comando del cliente si existe (`porter output <ID-A> stdout` / `stderr`), o directamente los archivos que registra el trabajo (`stdout_path` / `stderr_path`, dentro de `/tmp/porter-tc`): `cat` de ambos.
6. Igual para B: `cat` de sus dos archivos.
7. `ls /tmp/porter-tc/` y anotar dónde quedaron los archivos.

## Resultado esperado
- Paso 4: A `FAILED` con código 3; B `SUCCEEDED` con código 0; C `FAILED` con código de señal (valor negativo `-9`, o el que documente el ADR de IPC), y el estado no es `CANCELED` porque nadie pidió cancelarlo.
- Paso 5: el archivo de stdout de A contiene exactamente `linea-out`; el de stderr, exactamente `linea-err`.
- Paso 6: stdout de B contiene `out1 out2 out3` en orden y ninguna línea `err`; stderr contiene `err1 err2 err3` y ninguna `out`.
- Paso 7: los archivos de salida están **dentro de `JOBRUNNER_DATA_DIR`** (RF-16), no en la carpeta desde donde se lanzó el servicio.
