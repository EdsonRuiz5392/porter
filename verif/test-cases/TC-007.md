# TC-007 — Reinicio y recuperación

**Requisitos cubiertos:** RF-12, RF-13, RNF-10, RNF-11, RNF-30, RNF-31.
**Nivel:** robustez. **Hito:** H2.

## Objetivo
Comprobar que, tras una caída con `kill -9`, el servicio conserva lo terminado, reanuda lo pendiente, marca lo interrumpido y no deja huérfanos.

## Precondiciones
Servicio reiniciado con la configuración de abajo y `/tmp/porter-tc` limpio, según la [preparación común](README.md).

## Entorno y configuración
Preparación común, con `JOBRUNNER_MAX_CONCURRENCY=3`.

## Datos de entrada
Un `echo antes`, tres `sleep 777` y un `sleep 1`.

## Pasos reproducibles
**Automatizado:**

```bash
python3 verif/scripts/run_verificacion.py --filtro tc007
```

**A mano:**

1. `porter submit echo antes` y esperar a `SUCCEEDED`.
2. `porter submit sleep 777` tres veces y `porter submit sleep 1`. Confirmar 3 `RUNNING` y 1 `QUEUED`.
3. `kill -9 <PID del servicio>`. Comprobar con `pgrep -f 'sleep 777'` que siguen 3 procesos.
4. Reiniciar el servicio.
5. `porter status` de cada trabajo y `grep -E 'INTERRUPTED|ORPHAN_KILLED' /tmp/porter-tc/jobrunner.log`.
6. `pgrep -f 'sleep 777'` y `porter health`.

## Resultado esperado
- Los tres `sleep 777` quedan `FAILED` con código -1 y evento `INTERRUPTED`.
- El `echo` no cambia.
- El `sleep 1` se reanuda y termina `SUCCEEDED`.
- No quedan procesos `sleep 777`; hay 3 eventos `ORPHAN_KILLED`.
- `health` reporta 0 en ejecución.
