# TC-001 — Enviar trabajo válido

**Requisitos cubiertos:** RF-01 (aceptar comando con argumentos y devolver ID único), RF-02 (rechazar entradas vacías o mal formadas con mensaje útil).
**Nivel:** sistema. **Hito:** H1.

## Objetivo
Comprobar que el sistema acepta un trabajo válido, devuelve un identificador único y distinto en cada envío, y rechaza una solicitud vacía con un mensaje claro sin afectar al servicio.

## Precondiciones
- Servicio arrancado según la preparación común del README, con `/tmp/porter-tc` recién creado.
- Cliente configurado en la terminal 2.

## Entorno y configuración
Los de la preparación común. Concurrencia 3, cola 20.

## Datos de entrada
| Paso | Entrada |
|---|---|
| 1 | `sleep 1` |
| 2 | `echo hola mundo` (comando con argumentos) |
| 3 | comando vacío `""` |

## Pasos reproducibles
1. `porter submit sleep 1` → anotar el ID devuelto (ID-A).
2. `porter submit echo hola mundo` → anotar el ID devuelto (ID-B).
3. `porter submit ""` → anotar la respuesta y el código de salida: `echo $?`.
4. `porter list` → confirmar que aparecen ID-A e ID-B y que no existe un trabajo con comando vacío.

## Resultado esperado
- Pasos 1 y 2: el cliente imprime un ID y estado `QUEUED` o `RUNNING`; termina con código de salida 0. ID-A ≠ ID-B.
- Paso 2: el trabajo registra el comando `echo` con los argumentos `hola mundo` (RF-01: "con sus argumentos").
- Paso 3: el cliente muestra un error que indica la operación y la causa (comando vacío); código de salida distinto de 0; el servicio sigue atendiendo (paso 4 funciona).
- Paso 4: `list` muestra exactamente dos trabajos.
