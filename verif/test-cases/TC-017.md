# TC-017 — Cancelaciones concurrentes

**Requisitos cubiertos:** RF-26, RNF-27.
**Nivel:** robustez. **Hito:** H2.

## Objetivo
Comprobar que cancelar varias veces a la vez, o justo después de enviar, produce un único estado final coherente.

## Precondiciones
Servicio reiniciado con la configuración de abajo y `/tmp/porter-tc` limpio, según la [preparación común](README.md).

## Entorno y configuración
Preparación común, con `JOBRUNNER_MAX_CONCURRENCY=3` (`50` para la cancelación inmediata), `JOBRUNNER_GRACE_SECONDS=3`.

## Datos de entrada
`sleep 30`, `sleep 2`, `echo rapido` y un `bash` que sale con 0 al recibir SIGTERM.

## Pasos reproducibles
**Automatizado:**

```bash
python3 verif/scripts/run_verificacion.py --filtro tc017
```

**A mano:**

1. Enviar `sleep 30` y lanzar 5 cancelaciones simultáneas con un cliente de prueba.
2. 20 veces: enviar `sleep 2` y cancelar de inmediato por otra conexión.
3. Cancelar el `bash` que sale con 0 al recibir SIGTERM.
4. Cancelar un trabajo ya terminado.

## Resultado esperado
- Las 5 cancelaciones responden `CANCELING`, con un solo evento `CANCELED`.
- Las 20 inmediatas responden `CANCELING` y terminan `CANCELED`.
- El `bash` queda `CANCELED` con código 0, porque se pidió antes de que terminara.
- El terminado responde `ALREADY_FINISHED` y sigue `SUCCEEDED`.

## Resultado observado
PASS en la corrida `2026-11-02_avance02-final` (Ubuntu 24.04, Python 3.12.3, commit `3755ec6`), ejecutada por Edson.
