# TC-019 — Desconexión durante una solicitud

**Requisitos cubiertos:** RF-28, RF-22.
**Nivel:** robustez. **Hito:** H2 (local) · H3 (remoto).

## Objetivo
Comprobar qué pasa con la operación si el cliente se desconecta, y que puede recuperar el ID con el folio.

## Precondiciones
Servicio reiniciado con la configuración de abajo y `/tmp/porter-tc` limpio, según la [preparación común](README.md).

## Entorno y configuración
Preparación común, con Valores por defecto.

## Datos de entrada
`echo` con y sin folio.

## Pasos reproducibles
**Automatizado:**

```bash
python3 verif/scripts/run_verificacion.py --filtro tc019
```

**A mano:**

1. Con un cliente de prueba, enviar un `submit` completo y cerrar la conexión con RST, sin leer la respuesta.
2. `porter list`.
3. Enviar la mitad de un mensaje y cerrar.
4. `porter list`.
5. Enviar un `submit` con folio, cerrar sin leer y reenviar la misma solicitud.

## Resultado esperado
- Mensaje completo: la operación queda **aceptada** y no aparece `Traceback`.
- Mensaje incompleto: queda **sin efecto**; no se crea nada.
- El reenvío con folio devuelve el mismo ID y hay un solo trabajo.
- El servicio sigue vivo.
