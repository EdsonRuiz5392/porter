# TC-013 — Configuración y salud

**Requisitos cubiertos:** RF-16, RF-24.
**Nivel:** sistema. **Hito:** H2.

## Objetivo
Comprobar que la configuración inválida impide arrancar con un mensaje claro, que la válida queda registrada y que `health` informa el estado.

## Precondiciones
Servicio reiniciado con la configuración de abajo y `/tmp/porter-tc` limpio, según la [preparación común](README.md).

## Entorno y configuración
Preparación común, con `JOBRUNNER_MAX_CONCURRENCY=1` para `health`; `MAX_CONCURRENCY=2` y `MAX_QUEUE=7` para el registro.

## Datos de entrada
`MAX_CONCURRENCY=0`, `-2` y `abc`; `MAX_QUEUE=0`; `PORT=99999`; `GRACE_SECONDS=-1`; `SHUTDOWN_TIMEOUT=x`.

## Pasos reproducibles
**Automatizado:**

```bash
python3 verif/scripts/run_verificacion.py --filtro tc013
```

**A mano:**

1. Arrancar con cada valor inválido y anotar el código de salida y el mensaje.
2. Arrancar con una configuración válida y buscar `SERVICE_STARTED` en la bitácora.
3. Enviar dos `sleep 3` y un `false`, y correr `porter health`.

## Resultado esperado
- Con cada valor inválido el servicio no arranca, termina con código distinto de 0 y muestra `Configuración inválida` con el nombre de la variable.
- `SERVICE_STARTED` incluye `concurrencia=2` y `cola=7`.
- `health` reporta activo, 1 en ejecución y 2 en cola; el cliente termina con código 0.
