# TC-018 — Solicitud duplicada

**Requisitos cubiertos:** RF-27.
**Nivel:** robustez. **Hito:** H2.

## Objetivo
Comprobar la semántica de ADR-007: un reintento devuelve el trabajo original, un folio con otro comando es un conflicto y el historial no se pierde. Agrupa TC-018a (con folio) y TC-018b (sin folio).

## Precondiciones
Servicio reiniciado con la configuración de abajo y `/tmp/porter-tc` limpio, según la [preparación común](README.md).

## Entorno y configuración
Preparación común, con Valores por defecto.

## Datos de entrada
Folios `F1` y `F2`; `pedido-1` para el cliente.

## Pasos reproducibles
**Automatizado:**

```bash
python3 verif/scripts/run_verificacion.py --filtro tc018
```

**A mano:**

1. TC-018a: `porter submit --request-id pedido-1 echo hola` dos veces.
2. `porter submit --request-id pedido-1 ls`.
3. `porter status <ID original>`.
4. TC-018b: enviar `echo igual` tres veces sin folio.
5. Con un cliente de prueba, 6 envíos simultáneos con el folio `F2`.

## Resultado esperado
- El reintento devuelve el mismo ID, en cualquier estado, con evento `DUPLICATE`.
- Otro comando con el mismo folio recibe `REQUEST_ID_CONFLICT` y el cliente termina con código 1.
- El trabajo original sigue intacto.
- Sin folio se crean 3 trabajos distintos.
- Los 6 simultáneos reciben un solo ID y hay una sola fila.
