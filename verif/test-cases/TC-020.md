# TC-020 — Terminación inesperada del proceso hijo

**Requisitos cubiertos:** RF-29, RNF-30.
**Nivel:** robustez. **Hito:** H2.

## Objetivo
Comprobar que un hijo que muere sin que nadie lo pida queda `FAILED` con diagnóstico, y que se liberan sus recursos.

## Precondiciones
Servicio reiniciado con la configuración de abajo y `/tmp/porter-tc` limpio, según la [preparación común](README.md).

## Entorno y configuración
Preparación común, con `JOBRUNNER_MAX_CONCURRENCY=3`; `1` para la falla de captura.

## Datos de entrada
`sleep 31` y señales SIGKILL, SIGTERM y SIGSEGV.

## Pasos reproducibles
**Automatizado:**

```bash
python3 verif/scripts/run_verificacion.py --filtro tc020
```

**A mano:**

1. Enviar `sleep 31` y obtener su PID con `porter status`.
2. `kill -9 <PID>` desde otra terminal.
3. `porter status <ID>` y `grep KILLED_BY_SIGNAL /tmp/porter-tc/jobrunner.log`.
4. Repetir con `kill -TERM` y `kill -SEGV`.
5. `porter health`.

## Resultado esperado
- Cada trabajo queda `FAILED` con código `-9`, `-15` o `-11`.
- Hay un evento `KILLED_BY_SIGNAL` por trabajo.
- `health` reporta 0 en ejecución.
- Si falla la captura, el trabajo queda `FAILED -1`, el proceso no sigue vivo y se respeta el límite.
