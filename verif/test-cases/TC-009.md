# TC-009 — Cierre controlado

**Requisitos cubiertos:** RF-15, RNF-25, RNF-30.
**Nivel:** sistema. **Hito:** H2.

## Objetivo
Comprobar que el servicio deja de aceptar trabajos al cerrar, termina en un tiempo acotado y no deja procesos.

## Precondiciones
Servicio reiniciado con la configuración de abajo y `/tmp/porter-tc` limpio, según la [preparación común](README.md).

## Entorno y configuración
Preparación común, con `JOBRUNNER_MAX_CONCURRENCY=2`, `JOBRUNNER_GRACE_SECONDS=2`, `JOBRUNNER_SHUTDOWN_TIMEOUT=2`.

## Datos de entrada
`sleep 61` y `bash -c "trap '' TERM; sleep 62"`.

## Pasos reproducibles
**Automatizado:**

```bash
python3 verif/scripts/run_verificacion.py --filtro tc009
```

**A mano:**

1. Enviar los dos trabajos y confirmar `RUNNING`.
2. `kill -TERM <PID del servicio>` y medir cuánto tarda en terminar.
3. Durante el cierre, `porter submit echo tarde`.
4. Revisar la base con `sqlite3` y `pgrep -f 'sleep 6'`.
5. Repetir con `Ctrl+C` en la terminal del servicio.

## Resultado esperado
- El envío durante el cierre recibe `SERVICE_CLOSING`.
- El servicio termina con código 0 en un máximo de `2 + 2 + 5` segundos, más un margen.
- El `sleep` queda `CANCELED -15` y el que ignora SIGTERM queda `CANCELED -9`.
- No quedan procesos.
- `Ctrl+C` hace el mismo cierre.
- Los `QUEUED` se conservan y corren al reiniciar.
- Con el puerto ocupado, el servicio termina con error sin lanzar trabajos.
