# TC-014 — Construcción desde clon limpio

**Requisitos cubiertos:** RNF-01 (ejecuta en la distribución declarada), RNF-02 (construcción reproducible desde un clon limpio con instrucciones documentadas), RNF-03 (sin privilegios de root).
**Relacionado:** RNF-16 (mínimo privilegio), RNF-20 (pruebas con un solo comando).
**Nivel:** aceptación. **Hito:** H1. Es también lo primero que hará el profesor en la RT-1: "construir el producto desde el repositorio".

## Objetivo
Comprobar que una persona sin ayuda del equipo puede clonar el repositorio en una máquina limpia, seguir únicamente el README, y llegar a ejecutar el servicio, enviar un trabajo y correr las pruebas automatizadas, todo como usuario normal.

## Precondiciones
- Una máquina o carpeta **sin copia previa** del proyecto. Se recomienda WSL2 o una carpeta temporal en la VM.
- Solo lo que declare el README como requisito previo (por ejemplo Python 3.12 y `git`).

## Entorno y configuración
Ubuntu 24.04 LTS (o la distribución que declare el README). Usuario sin privilegios. Registrar: `lsb_release -ds`, `uname -m`, `python3 --version`, `id -u`, commit probado.

## Datos de entrada
El README del commit bajo prueba. Nada más.

## Pasos reproducibles
1. `mkdir -p /tmp/clon-limpio && cd /tmp/clon-limpio && git clone https://github.com/EdsonRuiz5392/porter.git && cd porter && git log -1 --oneline`.
2. `id -u` → anotar (debe ser distinto de 0).
3. Seguir **al pie de la letra** la sección de instalación del README. Anotar cada comando y si tuvo que consultarse algo fuera del README.
4. Seguir la sección de ejecución: arrancar el servicio y, en otra terminal, `porter submit true`, `porter status <id>`.
5. Seguir la sección de pruebas: el comando único documentado (por ejemplo `python -m pytest verif/scripts -v`).
6. Detener el servicio con Ctrl+C.
7. `rm -rf /tmp/clon-limpio`.

## Resultado esperado
- Paso 1: clon exitoso.
- Paso 2: no es root.
- Pasos 3 a 5: cada paso funciona con las instrucciones del README, sin pedir `sudo` (salvo instalar `python3-venv` si el README lo declara como requisito del sistema) y sin necesitar preguntar al equipo.
- Paso 4: el trabajo termina `SUCCEEDED`.
- Paso 5: la suite corre con un solo comando y reporta resultados.
- Paso 6: el servicio termina de forma limpia, sin procesos huérfanos: `pgrep -f src.servicio.main` vacío.
